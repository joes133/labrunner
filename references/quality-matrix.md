# 定档判定细则

阶段 3 使用。作用：帮模型给出**有依据的推荐**，但决定权始终在用户。

---

## 一、质量档

| 档 | 图片 | 水印 | 执行要求 | 典型耗时 |
|---|---|---|---|---|
| 高 | 关键步骤 + 重要结果必配 | 有（学号姓名） | 全程真跑 | 最长 |
| 中 | 视情况，可有可无 | 无 | 全程真跑 | 中等 |
| 低 | 无 | 无 | 全程真跑 | 最短 |

**判断线索**

| 观察到的信号 | 倾向 |
|---|---|
| 资料中出现「截图」「运行结果图」「现象记录」「附运行结果」 | 排除低，至少中 |
| 资料明确要求「实验过程截图」「结果截图」 | 倾向高 |
| 纯推导、算法题、无 GUI 产出 | 倾向低 |
| 有 GUI 演示、需要证据链（OS、组原、网安） | 倾向高 |
| 用户赶时间 / 表示「差不多就行」 | 倾向低或中 |
| 报告占总评比例高、老师严格 | 倾向高 |

**注意**：质量档只影响**产出形态**，不影响「是否真跑」。
任何档位都必须真实执行，跑不通就降级并告知（不会因选低档而跳过执行）。

---

## 二、执行模式

| 模式 | 触发条件 | 用户需要做什么 |
|---|---|---|
| A 全自动真图 | 截图能力 L2 | 只授权；跑的过程中不要动鼠标键盘 |
| B 协作真图 | 截图能力 L1 或 L0，且资料强制要图 | 按《请截图清单》截图，或手动摆好窗口 |
| C 无图文字 | 资料不要求图，或环境完全不可控 | 不动手 |

**决策树**

```
资料是否硬性要求图片？
├─ 否 -> 推荐 C（若用户想要图，再评估 A/B）
└─ 是 -> 环境探测结果？
        ├─ L2 -> 推荐 A
        ├─ L1 -> 推荐 A（配全屏裁切）或 B
        └─ L0 -> 推荐 B（出清单）；若用户不愿配合 -> 告知后走 C
```

**降级规则（用户已确认采用）**
先尝试完整执行；确实跑不通才降级。
降级时必须明确告知用户：降级了哪一步、为什么、对报告有什么影响。

## 四、时间预估

**定档时给粗估区间**，等阶段 4 拆完实际步骤后**修订一次**。

构成模型：

```
预计耗时 = 环境准备 + Σ(单步执行 + 截图开销) + 报告撰写 + 校验交付
```

参考基准（单次实验，仅供起点，务必按实际步骤数修正）：

| 档 | 基准区间 |
|---|---|
| 高 | 40 - 70 min |
| 中 | 25 - 45 min |
| 低 | 15 - 30 min |

**输出格式**

```
预计耗时：约 25 - 35 分钟
构成：环境准备 5 + 实验执行 6步 x 3min + 截图/水印 8 + 报告撰写 10 + 校验 3
预计交付：今天 21:10 前
```

写预估时宁可保守，也不要报一个漂亮但做不到的数字——
阶段 8 复盘会拿这个数字打你的脸。
